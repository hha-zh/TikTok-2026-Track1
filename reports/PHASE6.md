## Authority × Budget interaction

Authority Γ and Budget / Execution Horizon B are parallel constraint dimensions
that jointly define the admissible runtime space. Adaptive routing chooses WHO
and HOW inside that space. Neither axis creates or rescues the other.

    hardEligible = hard governance + real hard runtime capacity
    planningFit = FITS_ESTIMATE | ESTIMATED_SHORTFALL
    routableNow = hardEligible && planningFit == FITS_ESTIMATE

`ESTIMATED_SHORTFALL` is planning information, not hard budget exhaustion.
Specialist-required or authority-forced work may expand agency without an
ordinary utility comparison; otherwise “smallest worthwhile” is a deterministic
demo/evaluation heuristic, not a global optimum.

## Architecture views

### System architecture

Authority Γ and Budget/Horizon B feed the admissible runtime space in parallel.
The GovernanceLedger spans the governed lifecycle as the append-only evidence
and event-driven runtime-feedback plane; it is not merely a post-execution log.

### Decision pipeline

    Task -> CandidateSnapshot -> AuthorityView + BudgetView
      -> hardEligible + planningFit -> routableNow
      -> Router -> WHO + HOW -> dispatch

### Runtime feedback loop

    Decision_t -> Execution_t -> actual outcome / tokens_consumed
      -> GovernanceLedger -> RunState / GrantState projections
      -> CandidateBuilder_(t+1) -> Decision_(t+1)

## Known limitation

HG-14 is PARTIAL. Model/Budget is mediated at DISPATCH granularity: once a run's
budget is exhausted no further dispatch occurs, but individual model calls made
inside one dispatch are not separately intercepted and are accounted post-hoc
from reported usage. `maxToolCalls` is retained metadata and is not enforced.
Complete mediation covers Bouncer-managed crossings only; arbitrary filesystem
or network access in danger-full-access and already-completed external effects
remain outside that claim. Token accounting is post-hoc, so one in-flight call
per principal may overshoot. Provider usage reporting is trusted.
